1. Modelagem de dados (DER) — tabelas e relacionamentos do DB_Delivery

PK chave primária  ·  FK chave estrangeira  ·  linhas 1 → N ligam cliente→pedido→itens e produto→itens.

2. Diagrama de fluxo — comunicação Front-End ↔ Back-End ↔ Banco de Dados

comunicação assíncrona (arquivo JSON — sem conexão direta entre os sistemas)
comunicação síncrona (ADO.NET / classe Conexao, via MySql.Data)

3. Por que essa arquitetura é assíncrona

Site e app nunca se conectam diretamente — não há API entre os dois. O site gera o pedidos.json a qualquer momento, mesmo com o app fechado; o arquivo fica esperando até o funcionário abrir o app e importar. Já o acesso ao banco (login, CRUDs, importação) é síncrono: o app chama a classe Conexao e aguarda a resposta do MySQL antes de continuar.

[
  {
    "cliente_email": "joao@email.com",
    "data_pedido": "2026-11-09 19:30:00",
    "forma_pagamento": "Pix",
    "endereco_entrega": "Rua A, 100 - Centro",
    "valor_total": 64.90,
    "itens": [
      { "produto_id": 2, "quantidade": 1, "preco_unitario": 49.90 },
      { "produto_id": 8, "quantidade": 1, "preco_unitario": 15.00 }
    ]
  }
]

O app C# localiza o cliente pelo cliente_email, insere o pedido em tblPedidos (status inicial "Recebido") e os itens em tblItensPedido.
